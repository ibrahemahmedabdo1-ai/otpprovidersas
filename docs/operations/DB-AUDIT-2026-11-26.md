### Cause of the size

Values are stored as `enc:v1` (uncompressed, 400 rows, **303 MB**) or `enc:v2` (compressed, 104 rows, **47 kB**). Same key types compare as: pre-key v1 averages about 456 kB per row, pre-key v2 about 250 bytes. Almost the whole table was written in one hour (2026-11-25 17:00 UTC: 376 rows, 303 MB), when the gateway re-encrypted legacy values. Nothing is older than 7 days.

### The compression migration does not appear to be progressing

`migrateOneLegacyAuthValue` is meant to convert one `enc:v1` row to `enc:v2` every 5 minutes, smallest first. Evidence from Neon:

- 175 of the 400 remaining v1 rows are under 2 kB (smallest 75 bytes). They would be converted first.
- The newest v1 update is 2026-11-25 21:26 UTC; the oldest v2 update is 21:30 UTC. After roughly 10 hours (about 120 ticks), none of the smallest v1 rows has been converted.
- The 104 v2 rows are consistent with normal gateway writes of new or changed keys (4–34 rows per hour).

The cause cannot be established from the database. Possibilities: the deployed gateway does not contain this function (Railway runs an inline start command that may differ from GitHub), the function returns early, or it fails and logs `AUTH_COMPRESSION_MIGRATION_FAILED`. Railway logs and the deployed version are needed.

### Operational impact of the size

Each gateway read of a v1 key transfers the whole value (up to 17–22 MB) from Neon. That is the main driver of Neon transfer and gateway memory use. After conversion the same rows would be roughly 1 000 times smaller.

### Retention and cleanup

- There are no duplicate or expired rows: 506 unique keys, none older than 7 days, 504 updated in the last 24 hours.
- Keys are managed by Baileys (it deletes keys it no longer needs). Any manual deletion of session, pre-key, sender-key or app-state rows can break decryption or force QR re-pairing. **No row-level cleanup is recommended.**
- Even after conversion the physical size stays near 358 MB: PostgreSQL reuses freed pages but does not return them. Shrinking the file needs a table rewrite (`VACUUM FULL` or a copy-and-swap).
